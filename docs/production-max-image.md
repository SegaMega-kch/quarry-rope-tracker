# Итоговая картинка «Отчёта за смену» и доставка в MAX

Статус на 10.10.2026: локальная реализация. Git, рабочий сервер и реальная группа MAX не изменялись.

## Действия мастера

1. Мастер заполняет показатели и причины.
2. Нажимает `Данные заполнены`.
3. Если есть пропуски, выбирает: вернуться к форме или сохранить неполный итог.
4. Сайт сохраняет неизменяемую итоговую версию и показывает готовые картинки.
5. Мастер просматривает все части и отдельно нажимает `Отправить в MAX`.

Предварительная версия сохраняется отдельной кнопкой и не может быть отправлена. Исправленная итоговая версия снова требует просмотра и отдельной отправки.

## Содержимое и визуальные правила

- Только Главный карьер и только экскаваторы с введёнными данными.
- Одна карточка экскаватора всегда целиком находится на одной картинке.
- Внутри карточки используется не более двух колонок показателей; исходная ширина 900 px рассчитана на уменьшение до экрана телефона.
- Если карточки не помещаются, создаётся следующая картинка; все картинки уходят одним сообщением без подписи.
- План, факт, отклонение и выполнение; времена погрузки по ЖД и типам БЕЛАЗ; ожидания; выход негабарита для авто; причины без сокращения.
- Фактическое время выше норматива и отрицательное отклонение — красные.
- Пустое значение — прочерк на бледно-красном фоне. Пустота не превращается в ноль.
- `Загрузка, %` намеренно не показывается, хотя остаётся в сохранённой версии.

## Настройка сервера

В production требуется абсолютный путь в `SHIFT_PRODUCTION_MAX_CONFIG`. Формат совместим с закрытой конфигурацией существующего MAX worker и читает только следующие поля:

```json
{
  "tokenFile": "/absolute/private/path/token.txt",
  "botId": "123",
  "botUsername": "existing_bot",
  "chatId": "-123",
  "chatTitle": "Рапорт мастера"
}
```

Допустимы существующие служебные поля `sourceDatabase` и `outboxDatabase`; незнакомые поля отклоняются. На первом этапе `chatTitle` должен точно совпадать с `Рапорт мастера`; это защищает от случайной отправки в другую группу. Токен не передаётся клиенту и не журналируется.

Перед POST сервер повторно получает сведения о боте, целевом чате и членстве бота. Загруженные изображения принимаются только через HTTPS URL официального домена MAX. Успешная отправка одной версии не повторяется. Если после начала отправки нельзя надёжно определить результат, версия помечается для ручной проверки и автоматический повтор блокируется.

## Локальная проверка

Без `SHIFT_PRODUCTION_MAX_CONFIG` предпросмотр работает, а кнопка отправки недоступна с честным пояснением. Макет можно пересобрать командой:

```powershell
npx tsx scripts/preview-production-report-image.ts
```

Результат записывается в игнорируемую папку `outputs/production-report-image`. Реальные сообщения эта команда не отправляет.
