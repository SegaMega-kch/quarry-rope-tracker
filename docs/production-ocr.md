# Распознавание фото и перенос в отчёт

Статус на 17.10.2026: Yandex Vision OCR работает на сервере; локально реализован простой маршрут `Распознать` → `Перенести в отчёт` → проверка обычной таблицы → `Отправить в MAX`. Публикация нового маршрута выполняется только после локальной пользовательской проверки.

## Выбор распознавателя

Локальный Tesseract проверен на двух предоставленных фотографиях. На хорошем фото он тоже теряет цифры и десятичные разделители: контрольное `10,57` прочитано как `1057`. Координаты таблицы не восстановлены. Его внутренний confidence не является оценкой правильности производственных данных. Эти результаты не доказывают непригодность других локальных движков; PaddleOCR пока не проверялся.

Используется явно включаемый российский провайдер Yandex Vision OCR, модель `table`. Хорошая фотография даёт структуру таблицы и большинство значений; плохая остаётся непригодной для автоматического импорта. Переносятся только строки с уверенно прочитанным номером экскаватора и корректные числовые значения. Необходимость разрешения компании на внешнюю обработку остаётся независимо от российского провайдера.

Официальные источники:

- [API распознавания](https://aistudio.yandex.ru/ru/docs/vision/ocr/api-ref/TextRecognition/recognize)
- [Модель table](https://aistudio.yandex.ru/ru/docs/vision/concepts/ocr/models)
- [Отключение логирования содержимого](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging)

## Настройка

Переменные задаются только на сервере, локально — в закрытом `.env.local`. Ключ нельзя помещать в Git, `NEXT_PUBLIC_*` или переписку.

```dotenv
PRODUCTION_OCR_PROVIDER=local
# Для явно согласованной внешней обработки:
# PRODUCTION_OCR_PROVIDER=yandex
# YANDEX_OCR_API_KEY=...
# YANDEX_OCR_FOLDER_ID=...
```

Распознавание наследует права раздела «Отчёт за смену» и не имеет отдельного белого списка. Раздел и OCR доступны администратору и точечно учётной записи `4 смена`; роль `shift` сама по себе доступа не даёт.

Локальная обработка использует поставляемые с зависимостями языковые модели, без их загрузки из интернета. Рабочему процессу не передаются API-ключи приложения. При ошибке переключения в облако нет. В режиме Yandex запрос использует `x-data-logging-enabled: false`, а пользовательская кнопка называется просто `Распознать`. Это не утверждение о сроках хранения/географии всей инфраструктуры провайдера — их нужно подтвердить отдельно до эксплуатации.

Блок фотографии полностью скрыт в обычной компьютерной версии. Он показывается только на телефонах и планшетах; сервер дополнительно проверяет мобильный заголовок интерфейса и User-Agent/Client Hints. Это защита от случайного использования с ПК, а не криптографический запрет для намеренно подменённого клиента. Разрешены камера и галерея. Пользователь должен снять крупно только раздел «Главный карьер».

Для локальной визуальной проверки при `RAPMAS_LOCAL_REVIEW=1` узкое окно до 800 px имитирует только видимость мобильного блока. Серверная проверка запроса при этом не ослабляется: отправка фото с компьютерным User-Agent по-прежнему отклоняется.

Серверный маршрут держит изображение в памяти, удаляет EXIF перед обработкой и не пишет фото в архив или журналы приложения. После ответа исходная фотография отбрасывается. При подтверждённом переносе отдельная БД сохраняет метаданные импорта, предупреждения и все распознанные ячейки раздела «Главный карьер» с исходным и нормализованным значением. Западный и Северный карьеры не сохраняются. Диагностический CLI ниже отдельно сохраняет локальные обработанные изображения в игнорируемый `outputs/production-ocr`; это не поведение сайта.

Ограничения: JPEG/PNG/WebP, до 10 МБ, 20 мегапикселей, минимум 1000×600; HEIC нужно преобразовать на телефоне. Один запрос на процесс одновременно, локальный таймаут 90 с, облачный 60 с. Для многопроцессного развёртывания нужны общая очередь и лимиты. Reverse proxy должен сохранять Host, разрешать тело запроса 11 МБ и ожидание не менее 100 с. Нагрузочный тест и промышленный лимит по пользователю пока не выполнены.

Целевые серверные тесты OCR, мобильного ограничения, PNG и конфигурации MAX прошли: 14 из 14. Физический сценарий загрузки с телефона остаётся пользовательской проверкой.

Последняя команда предназначена только для локального стенда `127.0.0.1:3100`. Она проверяет авторизацию, запрет чужого Origin, обязательный мобильный контекст, формат запроса, реальные фотографии и неизменность истории отчёта. API Yandex дополнительно проверяется имитацией ответов/ошибок в unit-тестах.

Локально проверены desktop- и mobile-размеры интерфейса, видимость кнопки и отсутствие внешнего горизонтального переполнения. Проверка на физическом телефоне после рабочего развёртывания ещё не выполнена; эмуляция размера и HTTP-проверка её не заменяют.

Фактически выполнено локально: 209 тестов без ошибок и успешная сборка `npm run build` (предупреждение Next о нативном `<img>` для blob-предпросмотра и защищённого PNG принято осознанно). HTTP-проверка на двух оригинальных фото подтвердила ограничения доступа, мобильный контекст, обработку фото и неизменность истории. Проверка исходников отдельным ревьюером завершена без открытых материальных замечаний.

HTTP-сценарии повторно прошли на локальной собранной версии (`next start`, порт 3100). Установка зависимостей сообщила о 16 уязвимостях в общем дереве проекта; отдельный аудит и обновление существующих зависимостей не выполнялись. Перед эксплуатацией требуется отдельная проверка, без автоматического `audit fix` поверх текущих изменений. Служебная копия дизайн-контекста устарела относительно DESIGN.md; в этой задаче она не обновлялась.

## Правила переноса

- `Смена 2` источника означает дневной период той же даты; `Смена 1` — ночь, начавшуюся предыдущей датой. Номер бригады берётся только из общего календаря rapmas.
- Планы всех категорий экскаватора суммируются после перевода тысяч м³ в м³; факты суммируются в м³. Исходные категории сохраняются раздельно.
- Думпкар переносится только ЖД-экскаватору, Б75313 — как 240 т, Б75131 — как 130 т; выход негабарита переносится только автоэкскаватору.
- Уверенно распознанные поля перезаписывают текущую рабочую форму. Комментарии, причины, ожидание, состояние, загрузка в процентах и непрочитанные поля сохраняются без изменений.
- Нечитаемое значение не становится нулём. Явный ноль сохраняется как ноль.

### Проверка Yandex Cloud 10.10.2026

Личный Yandex Cloud настроен: отдельный сервисный аккаунт `rapmas-vision-ocr`, роль `ai.vision.user`, API-ключ с областью `yc.ai.foundationModels.execute`. Секрет хранится в закрытых локальной и серверной настройках, не входит в Git и не выводился. Запросы отправлялись с `x-data-logging-enabled: false` после отдельного разрешения пользователя.

- Плохое фото: ответ `200`, таблица 12×21, только 6 непустых ячеек. Заголовок, дата и почти все показатели не прочитаны — фото непригодно для импорта.
- Хорошее фото: ответ `200`, таблица 25×25, 145 непустых ячеек. Прочитаны дата, смена, Главный карьер и многие показатели, включая `8,72`, `10,57`, `5,30`, `4,90`, `7,96`, `3,30`, итоговые `9,04` и `4,72`.
- Yandex объединил строки экскаваторов `46` и `58` (`46 58`) и их времена (`5,30 4,90`). Такая объединённая строка не считается уверенно распознанным номером и автоматически не переносится.
- Две пустые служебные ячейки пересекали объединённый заголовок `№ экск`. Парсер теперь удаляет только пустой дубликат 1×1 внутри содержательной объединённой ячейки; конфликт двух непустых значений по-прежнему отклоняется.

Сырые ответы теста лежат только в игнорируемом каталоге `outputs/production-ocr`. Они не являются архивом сайта и не переносятся в Git.
